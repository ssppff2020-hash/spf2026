# C1 翻译流水线（pipeline）

> 把一门课的英文公开资料，变成可复用、可抽检的中文资料包。
> 本目录是**可复跑**的实现：换一门课，改 `config.yaml` 与 `manifest`，同样 5 步再跑一遍。

## 快速开始（换一门课怎么用）

```bash
# 0) 准备：把新课程的离线缓存/PDF 放到任意目录
# 1) 抓取缺漏（可选，网络可达时）
bash pipeline/01_fetch.sh materials/_work/live

# 2) HTML → 纯文本
python pipeline/02_extract.py <解压后的课程目录> materials/_work/extracted

# 2b) PDF → 纯文本（双引擎 + 健全性打分，别只用 pdftotext）
python pipeline/02b_extract_pdf.py <pdf 目录> materials/_work/extracted_pdf

# 3) 归一化成语料 + 清单（改 03_build_corpus.py 顶部的 MAP 表）
python pipeline/03_build_corpus.py

# 4) 翻译：把 04_translate_prompt.md 当作提示词交给 AI（或人），按 §1 的模板产出到 C1/翻译/
#    本资料包用「一个批次一个 agent、批次间共享同一份术语表」的方式并行翻译。

# 5) 质检
python pipeline/05_qa.py
#    → 生成 pipeline/qa_report.md
```

## 五步各自解决什么问题

| 步骤 | 文件 | 输入 → 输出 | 解决的真实问题 |
|---|---|---|---|
| 1 获取 | `01_fetch.sh` | 目标 URL → `live/` | 离线缓存有洞：页面被门禁、JS 渲染、或干脆没抓到。含 Notion 页面走 API、PPT 页抓不到就找演讲字幕替代 |
| 2 抽取 | `02_extract.py` | `.html` → `.txt` | 三种翻车：编码错乱、站点外壳混入正文、标题层级丢失 |
| 2b 抽 PDF | `02b_extract_pdf.py` | `.pdf` → `.txt` | **抽取器会静默损坏正文**：poppler 把某份 PDF 的每个字母抽了两遍（且少抽 33% 内容），不报错、看起来仍像正常英文。双引擎 + 重复率打分自动择优选 |
| 3 归一 | `03_build_corpus.py` | 散落文件 → `source/<slug>.txt` + `manifest.json` | 把「一堆文件名」变成「有 slug / 周次 / 标题 / URL / **输出路径** / 字数」的可调度清单 |
| 4 翻译 | `04_translate_prompt.md` | `source/*.txt` → `C1/翻译/**/*.md` | 统一译名、统一格式、禁止漏译与脑补；批次并行但共用一份术语表 |
| 5 抽检 | `05_qa.py` | 译稿 → `qa_report.md` | 覆盖度、禁用译法、小节数比对、篇幅下限、待回填术语 |

## 设计上的三个取舍（也是踩过的坑）

1. **不去追求"完美解析器"，而是让抽取器和译者分工。**
   通用 HTML 抽取器永远去不干净所有站点外壳（每个站的结构都不一样）。
   所以 `02_extract.py` 只做**能通用地做好**的三件事（编码、`<main>` 收窄、标题层级），
   剩下的残余噪声（页脚、订阅框、"相关文章"）交给步骤 4 的提示词约束，再由步骤 5 的禁用词扫描兜底。
   这比写一堆 per-site 的 CSS 选择器更经得起"换一门课"。

2. **质量靠"信号"而不是"自评"。**
   `05_qa.py` 不输出"合格/不合格"，只输出五个可核对的数字和一份需要人看的清单。
   覆盖率、禁用词命中数、小节数比例、篇幅下限——都是别人能独立复算的。

3. **术语表是唯一事实源。**
   术语不在提示词里散落，而在 `glossary.csv` 里集中维护；批次再多，也读同一份表。
   `05_qa.py` 的禁用词表就是从"实际抽检发现的多译"回填进去的（见 `C1/术语表.md` 修订记录）。

4. **凡是"没报错但结果错"的环节，都要有一个能自动说不的指标。**
   本次两个最危险的问题都是静默的：poppler 把一份 PDF 的每个字母抽两遍（`02b` 的**重复率**指标抓到），
   一个批次只译了 10 节中的 3 节（`05_qa` 的**篇幅下限**指标抓到）。
   两个指标都是可计算的数字——**正因为可计算，才能在不读全文的情况下发现问题**。
   反过来，看起来更"聪明"的结构比对（小节数）反而误报了一次。
   所以：**宁要一个简单但不被污染的指标，不要一个聪明但会失真的指标。**

## 已知限制

- `01_fetch.sh` 依赖外网可达。本环境里 `medium.com` 在**网络层不可达**，`blog.stockapp.com` **DNS 解析失败**，这两篇因此留有缺口。
- `02_extract.py` 的 `<main>/<article>` 收窄是启发式的：遇到既没有 `<main>` 也没有 `<article>`、
  正文全塞在普通 `<div>` 里的站点（如 Claude Code 文档站），仍会带进侧栏导航，需在步骤 4 排除。
- 步骤 4 目前是"AI 翻译 + 提示词约束"，没有接入机器翻译 API；
  要接 DeepL/Google MT，替换这一步即可，其余四步不用动。
