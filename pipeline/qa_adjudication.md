## A1 · 篇幅下限未达标 → 真问题（已修复）

**信号：**

```
C1/翻译/week04-Claude-Code与智能体编码/01-Anthropic如何使用Claude-Code.md
  中文字符 2,922 ｜ 下限 4,023  ⚠
```

**核对过程：**

1. 打开译稿，**格式完全正确**：文档头 6 行齐全、术语无误、中文通顺；
2. 但文件**末尾有一行** `<!-- PART-A-END -->` —— 这是译者分批处理时的分段标记，**没有清理**；
3. 对照原文目录：原文有 **10 个小节**，译稿只覆盖到第 3 个（安全工程），
   后面 7 节（推理 / 数据科学 / API / 增长营销 / 产品设计 / 强化学习工程 / 法务）**完全缺失**。

**结论：真问题——只译了 3/10 节。**

**为什么值得记录：** 这份译稿"读起来完全正常"。如果没有篇幅下限这个**可计算的**指标，
仅靠人眼扫一遍，几乎不可能发现它少了 70%。

**处置：** 重新派单补译剩余小节；复核后篇幅达标（见 `qa_report.md` 最新一次运行）。

## A2 · 小节数比对未达标 → 误报（已修检查项）

**信号：**

```
01-代码评审去做就对了.md ｜ 原文实质小节 7 ｜ 译文小节 0 ｜ 0.00 ⚠
```

**核对过程：**

1. 打开原文（`source/code-reviews-just-do-it.txt`），看到 7 个"小节"标题分别是：
   `Related posts`、`Civilized Discourse Construction Kit`、`How to Stop Sucking and Be Awesome Instead`、
   `Books: Bits vs. Atoms`、`The Vast and Endless Sea`、`Recent Posts`、`Launching The Rural Guaranteed Minimum Income Initiative`……
2. **全部是页面右侧的推荐位导航**，不是文章小节；
3. 打开译稿核对：Jeff Atwood 的这篇短文**正文本身就没有小节标题**，
   译文从引文到结论完整、连贯，**没有漏任何内容**。

**结论：误报——是检查项把站点导航数成了文章小节。**

**根因：** 站点导航用的是和正文一样的 `<h2>` / `<h3>` 标签，
`02_extract.py` 只能按标签抽，区分不了"导航标题"和"小节标题"。

**已做的修复（两层）：**

| 层 | 措施 |
|---|---|
| 检查项 | 给结构比对加过滤：**只统计"后面跟着 ≥150 字符正文"的标题**（导航项后面跟的是另一个标题，不是段落），并在 `05_qa.py` 顶部写明这条设计的原因 |
| 文档 | 本裁定记录 + `拿来说明 ③` 如实记录"结构比对误报 1 次、篇幅比对命中真问题 1 次"，并总结"简单指标胜在不会被污染" |

**为什么不干脆删掉这个检查项？**
因为它仍有价值——它能抓到"整段小节被吞掉"的情况，只是**会有误报**。
所以保留为 ⚠ 信号、人工确认，比删掉更合适。**但要写清它为什么会误报**，否则下一个人会把它当真理。

## A3 · PDF 抽取字符重复 → 真问题（已修复）

**信号：** 不是 `05_qa.py` 报的，而是在 A1 核对时**顺带看出来的**：

```
Claudee Code for dattaa infraassttrruucctuturere
HHooww AAnntthrrooppicic tteeaammss uussee CCllaauuddee CCooddee
```

**核对过程：**

1. 量了一下该 PDF 的"重复词"占比：**25.5%**（正常英文约 0%）；
2. 换成 `pymupdf` 重抽同一份 PDF：**0.0%**，而且总字符数从 56K 涨到 **75K**——
   poppler 在重复字符的同时**还丢了 33% 的内容**；
3. 另外两份 PDF 用两个引擎抽出来都正常。

**结论：真问题——`pdftotext` 静默损坏了这份 PDF。**

**处置：**
- 新增流水线步骤 `02b_extract_pdf.py`：双引擎抽取 + 重复率打分，自动择优选；
- 用干净原文**整篇重译**该文件；
- 教训写入 `AI日志/2026-10-05-02` 第 6 节（教训 7：**"没报错"不等于"抽对了"**）。

**为什么值得记录：** 三类失败里最危险的一类——不报错、看起来像正常文本、页数正确。
它差点以"翻译完成"的状态交付出去。

## A5 · 文件名大小写不一致 → 真问题（轻微，已修复）

**信号：** 不是脚本报的，是人工抽读那篇重译长文时看到的：

```
译文：...会读取他们的 Claude.md 文件（文档）...
应为：...会读取他们的 CLAUDE.md 文件（文档）...
```

**核对过程：** 全库扫描，`Claude.md` 出现 **6 次**（全部在这一篇），`CLAUDE.md` 出现 3 次。
术语表 §7 明确要求"文件名一律保留英文原名"，而原名是**全大写**的 `CLAUDE.md`。

**结论：真问题——大小写不一致，会误导读者以为文件名是 `Claude.md`。**

**处置：** 6 处全部改为 `CLAUDE.md`；修复后全库复扫，`Claude.md` 归零。

**顺带检查：** 全文只有 2 处出现裸的「代理」，且都是 `本地代理`（local **proxy**，指代理服务器），
**不是把 agent 误译成代理** —— 说明术语禁令是有效的。

> **为什么值得记录**：这是一个**脚本抓不到、只有人读才能发现**的问题。
> 它说明了自动质检的边界——五项检查能挡住"大段漏译、术语漂移、抽取损坏"，
> 但**挡不住"看起来对但细节错"**。所以自动抽检 + 人工抽读，两者都不能省。

## A6 · 抓到的文件不是该抓的文档 → 一例真问题、一例非缺陷

**信号：** 不是脚本报的，是**译者在完工报告里主动上报的**。两篇译文各报了一条：

> 「源文件 `claude-code-best-practices.txt` 的实际内容**不是**《Claude Code: Best Practices》，
> 而是文档站的 **Overview 页面**……我已按分配的元数据填了文档头，正文则 100% 忠实翻译了文件里实际存在的内容，**未做任何替代或补写**。」

> 「`owasp-top-ten.txt` 原文中**并未出现** A01:2021~A10:2021 那十条风险名……
> 按规范「不许编造」，我没有凭空补入十大风险列表。」

**核对过程（逐条去验证，不直接采信）：**

| 篇目 | 证据 | 裁定 |
|---|---|---|
| Week 4《Claude Best Practices》 | 文件首行是 `Claude Code overview - Claude Code Docs`，正文为 Get started / What you can do / Next steps。课程链接的 `anthropic.com/engineering/claude-code-best-practices` 现 **302** 到 `code.claude.com/docs/en/best-practices`，爬虫跟丢了跳转，落到了文档站首页 | **真问题**——缓存里是**错的文档** |
| Week 6《OWASP Top Ten》 | `grep -c "A0[1-9]:2021"` → **0**，文件是项目落地页。但课程大纲链接的就是 `owasp.org/www-project-top-ten/` 这个落地页，**抓到的正是大纲指向的页面**；十大风险本身在子页面 | **非缺陷**——缓存内容与大纲一致 |

**处置：**

- Week 4 那篇：`curl` 重抓真文章（200 / 740KB → 抽出 32,967 字符 / 31 小节），
  `03_build_corpus.py` 改 `source_file` 指向 `live/best-practices.txt`，
  `01_fetch.sh` 新增 B4 段把"错页面修复"变成流水线的一步，然后**整篇重译**；
- Week 6 那篇：**不改**。在 `01_fetch.sh` 的注释里写明它为什么不改，避免下一个人"顺手也修一下"。

**为什么值得记录：**

这是**自动质检永远抓不到**的一类错误——页面正常、长度正常、无重复字符、无乱码。
`05_qa.py` 五项检查全部会放行。

它被发现的唯一原因是：**规范写死了"不许编造、拿不准就顶上来说"，
译者因此把偏差报了上来，而不是按任务表里的标题编造一篇"最佳实践"。**

> **流程层面的结论**：自动化能做的是"可计算的不变量"（覆盖率、重复率、篇幅）；
> **"这份文件是不是它自称的那份"是语义判断，只能由读的人发现**。
> 两者之间必须留一条**上报异常的通道**——这次它生效了。
