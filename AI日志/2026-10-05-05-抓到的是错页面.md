## 1. 这次是子智能体先发现的

33 篇译完后，各批次陆续回报完成情况。其中两条报告里带着**不该被忽略的话**：

> **子智能体 tr-w4 的回报（原文照抄）**：
> 「一处需要你知道的偏差：源文件 `claude-code-best-practices.txt` 的实际内容**不是** Anthropic 工程博客的《Claude Code: Best Practices》，
> 而是 Claude Code 文档站的 **Overview 页面**（页面标题为 "Claude Code overview - Claude Code Docs"）。……
> 所以是抓取环节拿错了页面（或该 URL 已 302 到 overview）。
> 我已按分配给你的元数据填了文档头（原文标题/URL 照任务表），正文则 100% 忠实翻译了文件里实际存在的内容，**未做任何替代或补写**。如果需要真正的 best-practices 文章，得在 `01/02` 抓取阶段重取。」

> **子智能体 tr-b13 的回报（原文照抄）**：
> 「`owasp-top-ten.txt` 原文中**并未出现** A01:2021~A10:2021 那十条风险名，只有「Translation Efforts」「2025 Data Analysis Plan」等正文。
> 按规范「不许编造」，我没有凭空补入十大风险列表；你给的官方中文译名仅作备查，未落盘。」

**这两条报告的价值极高。** 它们说的是同一件事：**抓到的文件是"错的页面"。**

而它们的处理方式**恰恰是规范要求的**：

1. 正文**忠实翻译**文件里实际存在的内容——**不脑补**；
2. **主动上报偏差**，而不是默默按任务表填个标题就交差。

> **这正是 `04_translate_prompt.md` §0 第 2 条「不许编造」和译注机制想要的效果。**
> 如果我当初写的是"请翻译《Claude Code 最佳实践》这篇文章"，AI 很可能就**照着标题编出一篇最佳实践**了。
> 因为规范要求"原文没写的一律不写"，它才会把问题**顶回来**给我。

## 2. 逐条核实

我没有直接采信，而是**逐个去验证**：

**核实 ①：`claude-code-best-practices` 到底是不是 Overview？**

```bash
head -c 400 materials/_work/source/claude-code-best-practices.txt
```

```
Claude Code overview - Claude Code Docs
Skip to main content
Claude Code Docs home page
Getting started
...
```

**确认。** 文件第一行就是 `Claude Code overview`，正文是 `Get started / What you can do / Use Claude Code everywhere / Next steps` ——
这是文档站的**总览页**，不是最佳实践文章。

`sitemap.json` 那边的证据也对得上：课程大纲链接的 `anthropic.com/engineering/claude-code-best-practices`
现在会 **302 跳转**到 `code.claude.com/docs/en/best-practices`，而资料包的爬虫跟丢了这个跳转，落到了文档站首页。

**核实 ②：OWASP 那篇是不是也拿错了？**

```bash
grep -c "A0[1-9]:2021\|A10:2021" materials/_work/source/owasp-top-ten.txt
# → 0
```

**确认十大风险列表确实不在文件里。** 文件内容是该项目的**落地页**（"The most current released version is the OWASP Top Ten 2025…"）。

**但这一篇结论不同 —— 它其实不是缺陷。** 课程大纲链接的就是 `https://owasp.org/www-project-top-ten/` 这个落地页，
资料包抓到的**正是大纲指向的那个页面**。十大风险本身在子页面里，落地页不含列表是**正常的**。

**所以 tr-b13 的处理是对的**：不编造 + 上报。**没有需要修的地方。**

## 4. 这件事的真正教训

**HTTP 200 + 文本通顺 ≠ 抓对了内容。**

这是我今天第三次遇到同一类问题了，前两次是：

| 次 | 现象 | 抓它的指标 |
|---|---|---|
| 一 | Notion 页返回 200 / 19.9KB，正文只有 95 字符的 JS 外壳 | 字符数 |
| 二 | `pdftotext` 把某 PDF 每个字母抽两遍 | 重复率 |
| 三 | **页面抓对了 HTTP，但抓错了文档** | **只能靠读** |

**第三次没有指标可算。** 页面正常、长度正常、没有重复字符、没有乱码 ——
唯一能发现它的方法，是**有人真的读了一遍原文，并注意到标题和内容对不上**。

> **所以这一条记在这里的原因，是我要承认自动化的边界**：
> `05_qa.py` 的五项检查**永远抓不到这一类错误**。它能算覆盖率、能算重复率、能算篇幅，
> 但**"这份文件到底是不是它自称的那份"**，是一个需要语义判断的问题。

**能在流程上做的补救只有一条，而这次它生效了**：
**让干活的环节负责"报告异常"，而不是"猜一个合理答案"。**

- 规范里写死了"不许编造、拿不准就顶上来说"；
- 译者因此把偏差**主动报了上来**，而不是按标题编一篇最佳实践交差；
- 我收到报告后去核实，才发现了这个自动质检永远发现不了的问题。

> **一句话**：**自动化的分工，不是"让机器做完所有事"，
> 而是"让机器做它能验证的，让人做只有人能判断的"，并且在两者之间留一条"上报异常"的通道。**
