Anthropic 内部各团队正在用 Claude Code 改造自己的工作流，让开发者和非技术岗位的员工都能承接复杂项目、自动化任务，并补上过去限制他们生产力的技能缺口。

通过采访我们自己内部的 Claude Code 重度用户，我们收集到了这些洞察：不同部门如何利用 Claude Code、它对他们工作的影响，以及给其他考虑采用它的组织的建议。

## Claude Code 用于数据基础设施

数据基础设施团队为全公司的团队组织所有业务数据。他们用 Claude Code 自动化例行的数据工程任务、排查复杂的基础设施问题，并为技术与非技术团队成员创建有文档记录的工作流，让他们能独立访问和操作数据。

### 主要 Claude Code 用例

**用截图调试 Kubernetes** 当 Kubernetes 集群宕机、无法调度新的 pod 时，团队用 Claude Code 来诊断问题。他们把仪表盘的截图喂给 Claude Code，让它逐个菜单地引导他们走完 Google Cloud 的 UI，直到发现一条提示 pod IP 地址耗尽的警告。随后 Claude Code 给出了创建新 IP 池并将其加入集群的确切命令，从而免去了让网络专家介入的必要。

**为财务团队准备的纯文本工作流** 团队向财务团队成员演示了如何编写描述自己数据工作流的纯文本文件，然后把它们加载进 Claude Code，实现全自动执行。完全没有编程经验的员工也能描述诸如「查询这个仪表盘、获取信息、运行这些查询、产出 Excel 输出」这样的步骤，Claude Code 会执行整个工作流，包括主动询问像日期这样必需的输入。

**新员工熟悉代码库** 当新的数据科学家加入团队时，会被引导使用 Claude Code 来浏览他们庞大的代码库。Claude Code 会读取他们的 CLAUDE.md 文件（文档），为特定任务找出相关文件，解释数据流水线的依赖关系，并帮助新人理解哪些上游数据源馈入到仪表盘。这取代了传统的数据目录与可发现性工具。

**会话结束时的文档更新** 团队让 Claude Code 在每个任务结束时总结已完成的工作会话并提出改进建议。这形成了一个持续改进的闭环：Claude Code 基于实际使用情况帮助打磨 CLAUDE.md 文档和工作流说明，让后续迭代更有效。

**跨多实例的并行任务管理** 处理长时间运行的数据任务时，他们会在不同项目的不同仓库中打开多个 Claude Code 实例。每个实例都保持完整的上下文，所以当他们在数小时或数天后切回来时，Claude Code 能准确记得他们当时在做什么、停在了哪里，从而实现真正的并行工作流管理，且不丢失上下文。

### 团队影响

**无需专业技能即可解决基础设施问题** 解决了通常需要拉入系统或网络团队成员才能处理的 Kubernetes 集群问题，用 Claude Code 来诊断问题并给出确切的修复方案。

**加速上手** 新的数据分析师和团队成员可以快速理解复杂系统，无需大量指导就能做出有意义的贡献。

**增强支持工作流** 能够处理大得多的数据量并识别异常（比如监控 200 个仪表盘），这是人工手动审阅不可能做到的。

**实现了跨团队自助服务** 毫无编程经验的财务团队现在也能独立执行复杂的数据工作流。

### 来自数据基础设施团队的建议

**编写详细的 CLAUDE.md 文件** 你在 CLAUDE.md 文件中把工作流、工具和预期记录得越好，Claude Code 的表现就越好。这让 Claude Code 在你已有现成模式的情况下，擅长处理诸如搭建新数据流水线这类例行任务。

**处理敏感数据时用 MCP 服务器而不是 CLI** 他们建议使用 MCP 服务器而不是 BigQuery CLI，以便更好地控制 Claude Code 能访问什么，尤其是处理需要日志记录或存在潜在隐私顾虑的敏感数据时。

**举办团队使用分享会** 团队举办了分享会，成员之间互相演示自己的 Claude Code 工作流。这有助于传播最佳实践，并展示出他们自己可能发现不了的不同用法。

## Claude Code 用于产品开发

Claude Code 团队用自己的产品来给 Claude Code 构建更新，扩展产品的企业级能力和智能体循环功能。

### 主要 Claude Code 用例

**用自动接受模式做快速原型** 工程师用 Claude Code 做快速原型：开启「自动接受模式」（shift+tab），搭建自主循环，让 Claude 写代码、跑测试、持续迭代。他们把自己不熟悉的抽象问题交给 Claude，让它自主工作，然后先审阅那个完成度 80% 的方案，再接手做最后的打磨。团队强调要从干净的 git 状态开始，并定期提交检查点，这样当 Claude 跑偏时能轻松回退掉不正确的改动。

**核心功能的同步编码** 对于触及应用业务逻辑的更关键功能，团队会与 Claude Code 同步协作，给出带有具体实现指令的详细提示词。他们实时监控整个过程，确保代码质量、符合风格指南、架构正确，同时把重复性的编码工作交给 Claude。

**构建 Vim 模式** 他们最成功的异步项目之一是为 Claude Code 实现 Vim 键位绑定。他们让 Claude 构建整个功能（尽管这并非优先事项），最终实现里大约 70% 来自 Claude 的自主工作，只经过几轮迭代就完成了。

**生成测试与修复 bug** 他们在实现功能之后用 Claude Code 编写全面的测试，并处理拉取请求评审中发现的简单 bug 修复。他们还利用 GitHub Actions 集成，让 Claude 自动处理 PR 上的评论，比如格式问题或函数重命名。

**探索代码库** 面对不熟悉的代码库（比如单体仓库或 API 这一侧）时，团队用 Claude Code 快速理解系统是怎么运作的。他们不再等 Slack 回复，而是直接问 Claude 要解释和代码引用，省下了大量切换上下文的时间。

### 团队影响

**功能实现更快** 成功实现了像 Vim 模式这样的复杂功能，其中 70% 的代码由 Claude 自主编写。

**开发速度提升** 可以快速做功能原型并在想法上迭代，而不会陷入实现细节里。

**通过自动化测试提升代码质量** Claude 生成全面的测试并处理例行的 bug 修复，在减少人工投入的同时维持高标准。

**更好地探索代码库** 团队成员无需等待同事回复，就能快速理解单体仓库中不熟悉的部分。

### 来自 Claude Code 团队的建议

**搭好自给自足的循环** 让 Claude 通过自动跑构建、测试和 lint 检查来验证自己的工作。这样 Claude 能更长时间自主工作，并自己发现错误，当你让 Claude 在写代码之前先生成测试时尤其有效。

**培养任务分类直觉** 学会区分适合异步处理的任务（边缘功能、做原型）和需要同步监督的任务（核心业务逻辑、关键修复）。产品边缘的抽象任务可以用「自动接受模式」处理，而核心功能则需要更密切的监督。

**写清晰、详细的提示词** 当组件名字或功能相似时，请求要极其具体。你的提示词写得越好越详细，就越能放心让 Claude 独立工作，而不会误改代码库中不该动的地方。

## Claude Code 用于安全工程

安全工程团队专注于保障软件开发生命周期的安全、供应链安全和开发环境安全。他们大量使用 Claude Code 来编写和调试代码。

### 主要 Claude Code 用例

**复杂的基础设施调试** 处理事故时，他们把堆栈跟踪和文档喂给 Claude Code，让它沿着代码库追踪控制流。这大幅缩短了生产问题的解决时间，原本需要人工扫代码 10–15 分钟才能搞懂的问题，现在大约 5 分钟就能理解。

**Terraform 代码评审与分析** 对于需要安全审批的基础设施变更，他们把 Terraform plan 复制进 Claude Code，问「这会产生什么影响？我会不会后悔？」这使得反馈闭环更紧，安全团队更容易快速评审并批准基础设施变更，减少了开发流程中的瓶颈。

**文档综合与运行手册** 他们让 Claude Code 读取多个文档来源，生成 markdown 运行手册、故障排查指南和综述。他们把这类浓缩后的文档当作调试真实问题的上下文，比翻遍整个知识库效率更高。

**测试驱动开发工作流** 过去他们的模式是「设计文档 → 拼凑的代码 → 重构 → 放弃测试」，现在他们改让 Claude Code 先给伪代码，带着它走测试驱动开发，并在卡住时定期介入引导，产出更可靠、更可测试的代码。

**上下文切换与项目上手** 在给「dependant」（一个用于安全审批工作流的 Web 应用）这类已有项目做贡献时，他们用 Claude Code 来编写、评审和执行以 markdown 编写、存放在代码库中的规格说明，从而在几天而不是几周内就能做出有意义的贡献。

### 团队影响

**缩短事故解决时间** 原本需要人工扫代码 10–15 分钟的基础设施调试，现在大约 5 分钟。

**改进安全评审周期** 为安全审批做的 Terraform 代码评审快得多，开发者不再因等待安全团队批准而被卡住。

**增强跨职能贡献** 团队成员能在几天内对项目做出有意义的贡献，而不是花几周建立上下文。

**更好的文档工作流** 从多个来源综合出的故障排查指南和运行手册，带来了更高效的调试流程。

### 来自安全工程团队的建议

**大量使用自定义斜杠命令** 整个单体仓库里所有自定义斜杠命令的实现，有 50% 来自安全工程。这些自定义命令简化了特定的工作流，加快了重复任务。

**让 Claude 先开口** 他们不再为了拿到代码片段而问一些很具体的问题，而是告诉 Claude Code「边做边提交你的工作」，让它自主工作、定期汇报，从而得出更全面的方案。

**把文档交给它** 除了写代码，Claude Code 在综合文档和生成结构化输出方面也很出色。他们提供写作样例和格式偏好，从而拿到能立刻用在 Slack、Google Docs 等工具里的文档，避免在界面之间来回切换的疲劳。

## Claude Code 用于推理（inference）

推理团队负责管理记忆系统，也就是 Claude 读取你的提示词、生成回复时用来存储信息的系统。团队成员，尤其是刚接触机器学习的人，可以大量使用 Claude Code 来弥补这块知识缺口、加速自己的工作。

### 主要 Claude Code 用例

**理解代码库与上手** 团队高度依赖 Claude Code，在加入复杂代码库时快速理解架构。他们不再手动翻 GitHub 仓库，而是让 Claude 找出哪些文件调用了特定功能，几秒钟就能拿到结果，无需问同事或手动搜索。

**生成带边缘用例覆盖的单元测试** 写完核心功能后，他们让 Claude 编写全面的单元测试。Claude 会自动补上遗漏的边缘用例，几分钟内完成原本要耗费大量脑力的工作，就像一个可以随时审阅的编程助手。

**讲解机器学习概念** 由于没有机器学习背景，团队成员依赖 Claude 来解释模型特有的函数和设置。原本需要上网搜索并阅读文档一小时的事，现在只要 10–20 分钟，研究时间减少了 80%。

**跨语言代码翻译** 在不同编程语言中测试功能时，他们说明想测什么，Claude 就用所需的语言（比如 Rust）写出逻辑，免去了仅为测试而学习新语言的需要。

**命令回忆与 Kubernetes 管理** 他们不用记复杂的 Kubernetes 命令，而是问 Claude 正确的语法，比如「怎么获取所有 pod 或 deployment 状态」，然后拿到基础设施工作所需的确切命令。

### 团队影响

**加速 ML 概念学习** 研究时间减少 80% —— 原来要上网搜一小时，现在只要 10–20 分钟。

**更快地浏览代码库** 能在几秒内找到相关文件并理解系统架构，无需问同事。

**全面的测试覆盖** Claude 自动生成带边缘用例的单元测试，在维持代码质量的同时减轻脑力负担。

**消除语言障碍** 能用 Rust 这类不熟悉的语言实现功能，而无需专门去学。

### 来自推理团队的建议

**先测试知识库功能** 试着问各种问题，看 Claude 能不能比搜索引擎更快给出答案。如果它更快更准，那就是你工作流里一个很有价值的省时工具。

**从代码生成入手** 给 Claude 具体指令，让它写逻辑，然后验证正确性。这有助于在把它用于更复杂的任务之前，先建立对它能力的信任。

**用它来写测试** 让 Claude 写单元测试能大幅减轻日常开发的压力。用好这个功能，就能在不花时间手动推演所有测试用例的情况下保持代码质量。

## Claude Code 用于数据科学与可视化

数据科学与 ML 工程团队需要精细的可视化工具来理解模型表现，但构建这些工具往往要求掌握他们不熟悉的语言和框架。Claude Code 让这些团队无需成为全栈开发者，也能做出生产级的分析仪表盘。

### 主要 Claude Code 用例

**构建 JavaScript/TypeScript 仪表盘应用** 尽管「对 JavaScript 和 TypeScript 所知甚少」，团队还是用 Claude Code 构建完整的 React 应用，用来可视化 RL 模型表现和训练数据。他们放手让 Claude 从零编写完整应用，比如一个 5,000 行的 TypeScript 应用，自己无需理解这些代码。这一点很关键，因为可视化应用的上下文相对较少，不需要理解整个单体仓库，从而可以快速做出工具原型，在训练和评测过程中理解模型表现。

**处理重复性的重构任务** 面对合并冲突，或者那种编辑器宏搞不定、又还不值得投入大工程去做的、半复杂程度的文件重构时，他们把 Claude Code 当作「老虎机」——先提交当前状态，让 Claude 自主工作 30 分钟，然后要么接受方案，要么推倒重来。

**创建持久化的分析工具，而不是用完即弃的 notebook** 他们不再构建会被丢掉的一次性 Jupyter notebook，而是让 Claude 构建可复用的永久 React 仪表盘，供未来的模型评测使用。这很重要，因为理解 Claude 的表现「是团队最重要的事情之一」——他们需要理解模型在训练和评测中的表现，而「这一点其实并不简单，只看单个数字往上涨，简单工具拿不到多少信号」。

**零依赖的任务委派** 对于完全陌生的代码库或语言中的任务，他们把整个实现委派给 Claude Code，利用它从单体仓库中收集上下文并执行任务的能力，自己完全不参与实际编码过程。这让团队能在自身专业之外的领域也保持生产力，而不必花时间去学新技术。

### 团队影响

**实现了 2–4 倍的时间节省** 原本枯燥但仍可手动完成的例行重构任务，现在完成得快得多。

**用不熟悉的语言构建了复杂应用** 尽管 JavaScript/TypeScript 经验极少，还是做出了 5,000 行的 TypeScript 应用。

**从一次性工具转向持久化工具** 不再用一次性的 Jupyter notebook，而是构建可复用的 React 仪表盘做模型分析。

**直接获得模型改进的洞察** 亲身体验 Claude Code，为开发更好的记忆系统、以及为未来的模型迭代做 UX 改进提供了输入。

**让决策由可视化驱动** 借助先进的数据可视化工具，更好地理解 Claude 在训练和评测中的表现。

### 来自数据科学与 ML 工程团队的建议

**把它当成老虎机** 让 Claude 工作之前先保存状态，让它跑 30 分钟，然后要么接受结果，要么重新开始，而不是试图带着修改意见跟它较劲。从头开始的成功率往往比修补 Claude 的错误更高。

**需要时打断它，要求更简单** 监督过程中，别犹豫，随时叫停 Claude 并问「你为什么要这么做？试试更简单的办法。」模型默认倾向于更复杂的方案，但对「换更简单的做法」这类要求反应良好。

## Claude Code 用于 API

API 知识团队负责 PDF 支持、引用和网页搜索这类功能，它们把额外的知识带入 Claude 的上下文窗口。在庞大复杂的代码库上工作，意味着不断遇到不熟悉的代码片段，为任何给定任务搞清楚该看哪些文件要花大量时间，动手改动之前还得先建立上下文。Claude Code 改善了这种体验：它充当向导，帮他们理解系统架构、找出相关文件、解释复杂的交互。

### 主要 Claude Code 用例

**第一步的工作流规划** 团队把 Claude Code 当作任何任务的「第一站」，让它指出修 bug、开发功能或做分析时该看哪些文件。这取代了以往动手前手动浏览代码库、收集上下文的耗时过程。

**跨代码库的独立调试** 团队现在有信心去处理代码库中不熟悉部分的 bug，而不是找别人帮忙。他们可以问 Claude「你觉得你能修好这个 bug 吗？我观察到的行为是这样的」，往往立刻就有进展；考虑到所需的时间投入，这在以前是不可行的。

**通过吃自家狗粮（dogfooding）测试模型迭代** Claude Code 会自动使用最新的研究模型快照，这成了他们体验模型变化的主要途径。这让他们在开发周期中直接获得模型行为变化的反馈，这是以往几次发布时他们没有体验过的。

**消除上下文切换的开销** 以往要把代码片段复制出来、把文件拖进 Claude.ai，还要大段解释问题；现在他们可以直接在 Claude Code 里提问，无需额外收集上下文，大幅降低了脑力开销。

### 团队影响

**处理不熟悉领域时信心提升** 团队成员能独立调试 bug、排查不熟悉代码库中的事故。

**在收集上下文上大幅节省时间** 省去了把代码片段复制、把文件拖进 Claude.ai 的开销，减轻了切换上下文的脑力负担。

**轮岗上手更快** 轮换到新团队的工程师能快速浏览不熟悉的代码库并做出有意义的贡献，无需大量咨询同事。

**开发者更开心** 团队表示日常工作中的摩擦减少，感觉更开心、更高效。

### 来自 API 知识团队的建议

**把它当作迭代伙伴，而不是一步到位的方案** 不要指望 Claude 立刻解决问题，而要把它当作一个和你共同迭代的协作者。这比试图第一次就拿到完美方案更管用。

**用它在不熟悉的领域建立信心** 别犹豫，去处理自己专业之外的 bug 或排查事故 —— Claude Code 让在原本需要大量上下文积累的领域独立工作变得可行。

**从最少的信息开始** 一开始只给出你真正需要的最小信息，让 Claude 引导你走完流程，而不是一上来就灌输大量解释。

## Claude Code 用于增长营销

增长营销团队专注于搭建付费搜索、付费社交、移动应用商店、邮件营销和 SEO 等效果营销渠道。作为一个只有一个人的非技术团队，他们用 Claude Code 自动化重复性的营销任务，并构建出传统上需要大量工程资源才能完成的智能体化工作流。

### 主要 Claude Code 用例

**自动生成 Google Ads 创意** 团队搭建了一个智能体化工作流，它处理含有数百条现有广告及其表现指标的 CSV 文件，找出表现不佳、值得迭代的广告，并生成符合严格字符限制的新变体（标题 30 个字符，描述 90 个字符）。该系统使用两个专门的子智能体（一个负责标题，一个负责描述），几分钟内就能生成数百条新广告，而不必在多个广告系列中手动创建。这让他们能规模化地测试和迭代，这在以前需要花费大量时间才能做到。

**用于批量生产创意的 Figma 插件** 他们不再手动复制和编辑付费社交广告的静态图片，而是开发了一个 Figma 插件，它能识别画框，通过替换标题和描述以程序化方式生成最多 100 个广告变体，把原本要花数小时复制粘贴的工作压缩到每批半秒。这带来了 10 倍的创意产出，让团队能在关键社交渠道上测试多得多的创意变体。

**用于广告系列分析的 Meta Ads MCP 服务器** 他们做了一个与 Meta Ads API 集成的 MCP 服务器，可以直接在 Claude Desktop 应用里查询广告系列表现、花费数据和广告效果，无需在多个平台之间来回切换做表现分析，省下了关键的时间 —— 在这里，每一点效率提升都会转化成更好的 ROI。

**带记忆系统的高级提示工程** 他们实现了一个初级记忆系统，记录各轮广告迭代中的假设和实验，让系统在生成新变体时能把此前的测试结果拉进上下文，形成一个自我改进的测试框架。这使得系统性的实验成为可能，而靠人工是没法追踪的。

### 团队影响

**重复性任务上的时间大幅节省** 广告文案创作从 2 小时缩短到 15 分钟，腾出时间做策略性的工作。

**创意产出提升 10 倍** 借助自动生成和 Figma 集成，团队现在能在各渠道上测试多得多的广告变体。

**像一个更大的团队那样运作** 团队能承担传统上需要专职工程资源才能完成的任务。

**重心转向策略** 团队可以把更多时间花在整体策略和搭建智能体化自动化上，而不是手动执行。

### 来自增长营销团队的建议

**找出有 API 支持的重复性任务** 寻找那些涉及重复动作、且所用工具带 API 的工作流（比如广告平台、设计工具、分析平台）。这些是自动化的最佳候选，也是 Claude Code 价值最大的地方。

**把复杂工作流拆成专门的子智能体** 不要试图在一个提示词或一条工作流里处理所有事情，而是为特定任务创建单独的智能体（比如他们的标题智能体和描述智能体）。这在应对复杂需求时更容易调试，输出质量也更好。

**写代码之前先充分头脑风暴和规划提示词** 前期花大量时间用 Claude.ai 把整个工作流想透，然后让 Claude.ai 生成一份完整的提示词和代码结构供 Claude Code 参考。另外，要一步步来，而不是索要一步到位的方案，免得 Claude 被复杂任务压垮。

## Claude Code 用于产品设计

产品设计团队支持 Claude Code、Claude.ai 和 Anthropic API，专长是构建 AI 产品。即便是非开发者，也能用 Claude Code 弥合设计与工程之间由来已久的鸿沟，无需与工程师反复来回，就能直接把自己的设计构想实现出来。

### 主要 Claude Code 用例

**前端打磨与状态管理改动** 以往为了视觉上的微调（字体、颜色、间距），他们要写大量设计文档、和工程师来回反馈好几轮；现在他们直接用 Claude Code 实现这些改动。工程师注意到他们在做「通常不会看到设计师去做的大规模状态管理改动」，这让他们能达到自己设想的精确质量。

**GitHub Actions 自动建单** 借助 Claude Code 的 GitHub 集成，他们只需提交描述所需改动的 issue/工单，Claude 就会自动给出代码方案，甚至不用打开 Claude Code。对于他们那长期堆积的打磨类任务，这形成了一条无缝的修 bug 和完善功能的工作流。

**快速交互式原型** 把设计稿图片粘贴进 Claude Code，他们就能生成完全可用的原型，工程师可以立即理解并在上面迭代；这取代了过去那种静态 Figma 设计稿要经过大量解释、再翻译成可运行代码的循环。

**发现边缘用例与理解系统架构** 他们用 Claude Code 梳理错误状态、逻辑流程和不同的系统状态，从而在设计阶段就识别出边缘用例，而不是到开发后期才发现，从根本上提升了初始设计的质量。

**复杂的文案改动与法律合规** 对于在全代码库中移除「research preview」这类措辞的任务，他们用 Claude Code 找出所有出现位置、审阅周边文案、与法务实时协调并落实更新 —— 这个过程只用了两次 30 分钟的通话，而不是一周的来回协调。

### 团队影响

**核心工作流被重塑** Claude Code 成了主要的设计工具，Figma 和 Claude Code 有 80% 的时间都开着。

**执行速度快了 2–3 倍** 以往需要和工程师反复来回的视觉与状态管理改动，现在直接就能实现。

**周期从数周变成数小时** 像 GA 发布文案这样原本要协调一周的复杂项目，现在两次 30 分钟的通话就完成了。

**两种截然不同的用户体验** 开发者获得的是「增强型工作流」（执行更快），非技术用户获得的是「天哪，我成开发者了的工作流」（以前不可能有的全新能力）。

**改进设计与工程的协作** 因为设计师提前理解了系统的约束和可能性，沟通更好，问题解决更快。

### 来自产品设计团队的建议

**让工程师帮忙把环境搭好** 让工程同事帮忙完成初始的仓库设置和权限配置 —— 技术上手对非开发者来说很有挑战，但一旦配置好，它就会给日常工作流带来颠覆性的改变。

**用自定义记忆文件引导 Claude 的行为** 写一段明确的说明，告诉 Claude 你是一个几乎没有编程经验的设计师，需要详细的解释和更小的增量改动，这会显著提升 Claude 回复的质量，也让它不那么吓人。

**用图片粘贴来做原型** 用 Command+V 把截图直接粘贴进 Claude Code —— 它很擅长读设计稿并生成可运行的代码，是把静态设计稿变成工程师能立即理解并在此基础上继续开发的交互式原型的利器。

## Claude Code 用于强化学习工程

强化学习工程团队专注于 RL 中的高效采样，以及跨集群的权重传输。他们主要用 Claude Code 编写中小型功能、调试和理解复杂代码库，采用包含频繁检查点和回滚的迭代式方法。

### 主要 Claude Code 用例

**在受监督的自主性下开发功能** 团队让 Claude Code 编写中小型功能的大部分代码，同时自己提供监督，比如为权重传输组件实现认证机制。他们以交互方式协作，让 Claude 主导，但在它跑偏时把它拉回来。

**生成测试与代码评审** 自己实现完改动后，他们让 Claude Code 补充测试或评审代码。这条自动化测试的工作流在例行但重要的质量保证任务上节省了大量时间。

**调试与错误排查** 他们用 Claude Code 调试错误，效果参差不齐 —— 有时它能立刻定位问题并补上相关测试，有时它难以理解问题所在，但总体而言，在它能起作用的时候是有价值的。

**理解代码库与分析调用栈** 他们工作流中最大的变化之一，是用 Claude Code 快速获取相关组件和调用栈的摘要，取代了人工读代码或生成大量调试输出。

**Kubernetes 操作指导** 他们经常问 Claude Code 一些原本要大量搜索才能搞定的 Kubernetes 操作问题，就配置和部署上的疑问立刻得到答案。

### 开发工作流的影响

**支持了实验式做法** 他们现在采用「试了再回滚」的方法，频繁提交检查点，这样就能测试 Claude 的自主实现尝试，不行就还原，从而更敢于做实验。

**加速了文档** Claude Code 会自动加上有用的注释，在文档上省下大量时间，不过他们也指出，它有时会把注释加在奇怪的地方，或者代码组织方式值得商榷。

**提速但有限制** 虽然 Claude Code 能「花相对很少的时间」实现中小型 PR，但他们承认它只有大约三分之一的概率一次成功，其余情况需要额外指导或人工介入。

### 来自强化学习工程团队的建议

**针对特定模式定制你的 CLAUDE.md 文件** 在 CLAUDE.md 文件里加一些说明，防止 Claude 反复犯工具调用上的错误，比如告诉它「用 pytest 而不是 run，不要不必要地 cd —— 直接用正确的路径。」这显著提升了一致性。

**采用大量使用检查点的工作流** 在 Claude 做改动时定期提交你的工作，这样当实验不成功时就能轻松回滚。这让开发可以采用更实验性的方式而不承担风险。

**先试一次性做完，再转为协作** 给 Claude 一个简短的提示词，让它先尝试完整实现。如果成功了（大约三分之一的概率），你就省下了大量时间；如果不成功，再切换到更协作、更有引导的方式。

## Claude Code 用于法务

法务团队是在试验中、以及出于了解 Anthropic 产品线的兴趣，发现了 Claude Code 的潜力。此外，一位团队成员有一个个人用例 —— 为家人制作无障碍工具，以及一系列展示该技术对非开发者威力的工作原型。

### 主要 Claude Code 用例

**为家人定制的无障碍方案** 团队成员为因医学诊断而存在说话困难的家人构建了沟通助手。他们只花一个小时，就用原生语音转文字做出了一个预测输入应用，它会推荐回复并用语音库念出来，填补了言语治疗师推荐的现有无障碍工具的空白。

**法务部门工作流自动化** 他们做了「电话树」系统的原型，帮助团队成员联系上 Anthropic 里对口的律师，展示了法务部门如何在传统开发资源之外，为常见任务构建自定义工具。

**团队协作工具** 管理者构建了 G Suite 应用，用于自动化每周团队更新并跟踪各产品的法务评审状态，让律师只需点几下按钮就能快速标记需要评审的事项，而不必再管理表格。

**用于验证方案的原型验证** 他们用 Claude Code 快速构建出可以向领域专家展示的可运行原型（比如把无障碍工具展示给 UCSF 的专家），以便在投入更多时间之前验证想法并找出已有的解决方案。

### 工作方式与影响

**在 Claude.ai 里规划，在 Claude Code 里构建** 他们采用两步流程：先用 Claude.ai 做头脑风暴和规划，再转到 Claude Code 做实现，并要求它放慢速度、一步步来，而不是一次性输出所有内容。

**视觉优先的方法** 他们经常用截图向 Claude Code 展示希望界面长什么样，然后基于视觉反馈迭代，而不是用文字描述功能。

**原型驱动的创新** 他们强调要克服害怕分享「傻气」或「玩具」原型的心理，因为这些演示能启发别人看到他们此前未曾考虑过的可能性。

### 安全与合规意识

**MCP 集成方面的顾虑** 作为产品律师，他们会立刻识别出深度 MCP 集成带来的安全影响，并指出随着 AI 工具访问越来越敏感的系统，保守的安全姿态会制造出障碍。

**合规工具化的优先级** 他们主张随着 AI 能力扩张而快速构建合规工具，并意识到要在创新与风险管理之间取得平衡。

### 来自法务部门的建议

**先在 Claude.ai 里做充分的规划** 在转到 Claude Code 之前，用 Claude 的对话式界面把你整个想法捋清楚。然后让 Claude 把所有内容总结成一份分步的提示词，用于实现。

**渐进式、可视化地工作** 让 Claude Code 放慢速度，一次只实现一步，这样你就能复制粘贴而不至于不堪重负。大量使用截图来展示你希望界面长什么样。

**即便不完美也要分享原型** 克服想要藏起「玩具」项目或未完成工作的冲动 —— 分享原型能帮助他人看到可能性，并在那些通常不往来的部门之间激发创新。
